# 修复设计与引用（v1.0.0）

按问题报告的五层路线实现。每层标注：**借用思想**（开源项目，见 [03-开源调研](03-开源调研.md)）与**落点**（模块 + 测试）。

## 第一层：结构约束解码

- **设计**：`schema.py` 手写结构校验器——字段名/类型/嵌套/必填/枚举；命名漂移用别名表识别（`NAMING_DRIFT`）并在深层校验前拦截，避免漂移字段产生噪音反馈。
- **思想源头**：Outlines 的"约束前移"；python-jsonschema 的校验语义（schema 文档化后可平替）。
- **消灭**：失败模式 2（类型漂移）、3（命名漂移）、4（必填省略）。
- **落点**：`tests/test_generation.py::TestFailureModeRepairs` F2/F3/F4。

## 第二层：校验-修复循环 + 显式降级

- **设计**：`generator.py`——生成 → 结构校验 →（通过后）引用/语义/业务校验 → 违规转结构化反馈回喂 → 重试（上限 3）→ 耗尽则返回 `status="degraded"`、`config=None`、完整失败原因清单。**降级是产品功能不是异常**：调用方拿原因清单转人工，附在工单里。
- **思想源头**：Instructor 的 reask；Guardrails 的 Validator 链与机读错误。
- **消灭**：失败模式 1（幻觉 ID 经反馈修正）、5（语义/业务违规修正）；顽固场景走降级（`test_stubborn_degrades_after_retry_limit`）。
- **关键约束**：返回状态只有 `ok`（全绿）与 `degraded` 两态，`test_no_intermediate_state` 对全部 12 场景扫描保证。

## 第三层：合法枚举注入与检索

- **设计**：`registry.py`（组件/模板/套餐/广告位约束 + `SCHEMA_VERSION`）作为唯一事实源；`validators.py` 的每条引用类违规都携带 `options`（如 `INVALID_COMPONENT_ID` 附全部合法组件 ID）——错误信息**教会模型下次怎么改**，也让降级工单里的人工一眼看到合法值。模板库 <100 项直接全量注入；增长后按源文档路线演进为语义检索 + 同义词扩展。
- **思想源头**：Guidance 的枚举注入；Guardrails 的结构化错误。
- **落点**：`test_f1_hallucinated_id_repaired` 断言 `attempts == 2`（首轮报幻觉、带 options 回喂、次轮收敛）。

## 第四层：编辑走 patch，不走全量（架构性消灭 F6）

- **设计**：`patch_engine.py` 实现 RFC 6902 风格 op 子集（add/remove/replace/move），叠加四层防护：
  1. **路径白名单**（默认 `/pages` 前缀）：影响范围断言，越界即拒（`PATH_NOT_WHITELISTED`）；
  2. **manual_locked 锁**：人工改过的节点，patch 触碰自身/祖先/后代、或以它为 move 源，一律拒绝（`LOCKED_NODE_TOUCHED`）；
  3. **全量重写防护**：对根 `/` 的任何 op 直接拒绝（`ROOT_REPLACE_FORBIDDEN`）——与锁无关，写进架构；
  4. **原子性 + 结构复检**：任一 op 违规则整个 patch 不应用；全部应用后重跑结构校验，破坏结构（如删光 pages）则回滚（`PATCH_BREAKS_STRUCTURE`）。
- **思想源头**：python-json-patch / RFC 6902（op 语义）；防护层为本仓库针对失败模式 6 的自研增量。
- **落点**：`tests/test_patch.py` P1–P7。

## 第五层：golden 回归评测集

- **设计**：`data/golden/` 8 对 需求→期望配置（3 正常 + 5 触发失败后修复）；`golden.py` 产出指标：一次通过率 / 收敛率 / 幻觉 ID 率。任何 prompt、schema、校验器、注册表改动跑 `python3 -m nl2config.cli regress` 即可量化影响；CI 每次推送强制回归。
- **思想源头**：Guardrails 的 Validator 可测性；Evals 惯例（promptfoo/openai-evals 的 golden set 模式）。
- **落点**：`tests/test_golden.py`；CI 步骤 `Run golden regression`。

## 显式不做（边界）

- 不绑定特定厂商 SDK：LLM 层只做 OpenAI 兼容协议适配（`llm.py`），凭证与模型全部走环境变量。
- 不做语义检索版枚举注入（模板库 <100 项，全量注入够用）。
- 不做 schema 文件化（待平台侧逆向整理正式文档，`SCHEMA_VERSION` 已预留）。
