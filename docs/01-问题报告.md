# 问题报告：自然语言 → 低代码配置生成不可用

- **严重度**：P0（阻断"内部 AI Agent 系统"核心价值——需求→配置自动化完全不可用）
- **影响面**：所有经 Agent 生成的站点配置；含计费/归因层面的业务事故风险
- **报告日期**：2026-10-13
- **状态**：未修复（本目录为基线 v0.1.0）

## 1. 现象

Agent 把中文口语需求交给 LLM 后，**裸输出 JSON 文本直接当作低代码平台配置使用**。产出的配置树频繁出现：解析报错、渲染白屏、双端打包崩溃、套餐外模块被售卖、渠道追踪归因错误。

根本矛盾：LLM 的原生输出空间是**自由文本**，而目标是带强约束的**配置树**。这不是 prompt 调优问题，是受限形式语言生成问题。

## 2. 四层约束全部失守

| 层次 | 约束内容 | 现状 | 违反后果 |
|---|---|---|---|
| 结构约束 | 字段名/类型/嵌套/必填/枚举 | ❌ 无校验 | 解析直接报错，配置作废 |
| 引用完整性 | componentId/templateId 必须真实存在 | ❌ 无校验 | 渲染找不到组件，白屏 |
| 语义约束 | 双端兼容矩阵、广告位上限 | ❌ 无校验 | 打包时才炸 / 超出售卖范围 |
| 业务约束 | 套餐白名单、渠道追踪参数格式 | ❌ 无校验 | 计费/归因事故，收入层面 |

注：`validators.py` 里校验代码已存在（平台侧散落逻辑），但生成管线根本没接——约束没进闭环等于不存在。

## 3. 失败模式清单

F1 幻觉 ID；F2 类型/枚举漂移；F3 命名风格漂移；F4 必填项省略；F5 语义违规（双端/广告位）；F6 全量重写覆盖人工修改；F7 约束冲突累积。逐条样本见修复仓库 `docs/01-问题报告.md`（两目录共用同一份问题定义）。
