# 问题报告：自然语言 → 低代码配置生成不可用

- **编号**：对应仓库 Issue #1
- **严重度**：P0（阻断"内部 AI Agent 系统"核心价值——需求→配置自动化完全不可用）
- **影响面**：所有经 Agent 生成的站点配置；含计费/归因层面的业务事故风险
- **报告日期**：2026-10-13
- **状态**：已修复（v1.0.0，PR #2）

## 1. 现象

Agent 把中文口语需求（例："首页要大气一点，视频放上面，广告位摆两排"）交给 LLM 后，**裸输出 JSON 文本直接当作低代码平台配置使用**。产出的配置树频繁出现以下问题并流入渲染/打包环节：解析报错、渲染白屏、双端打包崩溃、套餐外模块被售卖、渠道追踪归因错误。

根本矛盾：LLM 的原生输出空间是**自由文本**，而目标是带强约束的**配置树**。这不是 prompt 调优问题，是受限形式语言生成问题——prompt 恳求换不来确定性。

## 2. 四层约束全部失守

| 层次 | 约束内容 | 现状 | 违反后果 |
|---|---|---|---|
| 结构约束 | 字段名/类型/嵌套/必填/枚举 | ❌ 无校验 | 解析直接报错，配置作废 |
| 引用完整性 | componentId/templateId 必须真实存在 | ❌ 无校验 | 渲染找不到组件，白屏 |
| 语义约束 | 双端兼容矩阵、广告位上限 | ❌ 无校验 | 打包时才炸 / 超出售卖范围 |
| 业务约束 | 套餐白名单、渠道追踪参数格式 | ❌ 无校验 | 计费/归因事故，收入层面 |

注：部分校验逻辑其实散落在平台代码中（`validators.py` 的雏形），但生成管线**根本没有调用**——约束没有接进闭环，等于不存在。

## 3. 失败模式清单（按实战频率排序）

| # | 失败模式 | 典型样本 | 复现测试 |
|---|---|---|---|
| F1 | 幻觉 ID | `componentId: "video_player_v2"`，库里只有 `video_player` | `test_f1_hallucinated_id_repaired` |
| F2 | 类型/枚举漂移 | `visible: "true"`（字符串布尔） | `test_f2_type_drift_repaired` |
| F3 | 命名风格漂移 | 同一棵树 camelCase/snake_case 混用 | `test_f3_naming_drift_repaired` |
| F4 | 必填项省略 | 漏 `templateId`，渲染时静默出错 | `test_f4_missing_required_repaired` |
| F5 | 语义违规 | iOS 配了不支持的 `live_stream`；广告位超套餐上限 | `test_f5_unsupported_platform_repaired` / `test_semantic_ad_limit_enforced` |
| F6 | 全量重写覆盖人工修改 | "换张 banner 图"→ 整棵树重新生成，20 处人工微调被无声覆盖 | `test_p4_root_replace_forbidden`（架构性防护） |
| F7 | 约束冲突累积 | 多轮修改后广告位超上限（跨轮次全局失忆） | 由 patch 白名单 + 全量校验的组合防护 |

## 4. 加重因素

- **schema 无文档**：配置结构散落在平台代码里，需先逆向整理 machine-readable schema（本仓库 `registry.py` + `schema.py` 即此项工作，带 `SCHEMA_VERSION`）。
- **schema 演进**：模板库持续新增，约束层必须版本化管理，否则每月一次静默腐化。
- **单人无评审**：校验规则写漏一条就是线上计费事故——因此校验器必须有 golden 回归兜底（第五层）。

## 5. 验收判据（怎么算修好）

| 判据 | 目标 | 实测（v1.0.0） |
|---|---|---|
| 结构合法率 | 100% | ✅ 100%（结构违规拦截后回喂） |
| 引用/语义一次生成合法率 | ≥ 95% | golden 一次通过率 37.5%（Mock 按最坏场景脚本化，属下界） |
| 含重试循环合法率 | ≥ 99.5% | ✅ 收敛率 100%（8/8） |
| 增量修改零覆盖人工配置 | 架构性保证 | ✅ 根替换被禁止、锁路径触碰即拒、破坏性测试全过 |
| golden 回归全绿 + 降级路径可达 | 必须 | ✅ 21/21 通过；stubborn 场景 4 次尝试后显式降级附原因 |

> 说明：Mock LLM 按失败场景脚本化输出，"一次通过率 37.5%"是**悲观下界**（12 个场景中刻意让 5 个 golden 场景首错）；真实模型接入后该指标才有业务意义，工程上保证的是"含重试收敛率 100% + 永不返回非法配置"。
